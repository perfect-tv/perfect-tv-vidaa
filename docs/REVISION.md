## 1. Ретранслятор: безопасность разбора (критично)

Порядок важен: сначала падения/порча памяти, затем производительность.

- [ ] **1.1. RTSP, Content-Length.** `src/core/relay.c:1641-1664`: проверять отрицательное значение,
      переполнение `hl + bl`, верхний предел тела; не отдавать размер из потока в `xstrndup`
      (`src/core/util.c:144-149`). То же для запросов сервера (`:1653-1662`).
      Критерий: `Content-Length: -1`, `18446744073709551615` и тело больше буфера — ошибка/415,
      без падения, без цикла.
- [ ] **1.2. RTSP, UAF.** `src/core/relay.c:1666-1668`: не делать `memmove` по `u->in` после
      `rtsp_fail`/`stream_data`, если `u` уже освобождён; проверка `u->dead` до работы с буфером.
      Критерий: ответы 401/404/`no_mp2t` и обрыв в разборе не оставляют обращений к освобождённой памяти.
- [ ] **1.3. HTTP-плейлист > 4 МБ.** `src/core/relay.c:1030-1040, 1112`: после `client_deliver`
      не продолжать `up_body`, если клиент закрыт; `client_reply_simple` помечает ответ отправленным
      (`head_sent`), `finishing` останавливает повторную выдачу тела и повторные `502`.
      Критерий: плейлист 4 МБ+ — один ответ, без UAF и без мусора в потоке плеера.
- [ ] **1.4. Флаг `again` в пуле.** `src/core/relay.c:695-705, 1163, 1853-1865`: сбрасывать
      `u->again` в `up_to_pool` (и при новом запросе). Критерий: после ответа с `SSL_pending() > 0`
      нет `epoll_wait(..., 0)` на 100 % CPU до 20 с.
- [ ] **1.5. DNS-задача.** `src/core/relay.c:724-737, 665`: при неудачной записи в трубу не оставлять
      `u->dns` висящим; освобождать задачу только после того, как цикл её забрал либо пометил
      `cancelled`. Критерий: нет записи в освобождённую задачу при переполнении трубы.

Коммиты — по одному на пункт, например:

```text
Ретранслятор: Content-Length RTSP проверяется (отрицательный, переполнение, предел тела), ответ сервера не зацикливает разбор
Ретранслятор: разбор RTSP не трогает буфер после rtsp_fail/stream_data — выход до memmove
Ретранслятор: плейлист больше 4 МБ закрывает соединение без UAF и повторных 502
Ретранслятор: again сбрасывается при уходе соединения в пул — нет холостого epoll_wait
Ретранслятор: неудачная запись DNS-задачи не оставляет висящий u->dns
```

## 2. Субтитры (критично/важно)

- [ ] **2.1. fMP4, границы образцов.** `src/core/webvtt.c:527-563`: `off`/`size` проверять без
      переполнения (`off > n`, `size > n - off`), ограничить размер образца; ограничить `cnt` и
      не крутить цикл, если `trun` не двигает `f` (`:536-543`).
      Критерий: сегмент с `base_data_offset = 2^64−k`, `size` и `sample_count` из потока не читает
      память вне сегмента и не занимает поток на минуты.
- [ ] **2.2. CEA-708, SPL/BS.** `src/core/cc.c:337, 292`: `pcol` ограничивать `cols - 1`, `BS`
      проверять `pcol < cols` перед записью. Критерий: `SPL` с колонкой 63 не пишет за
      `t[15][42]`.
- [ ] **2.3. DVB, размер области.** `src/core/dvbsub.c:161-165, 352-362, 407-415`: область не больше
      экрана (1920×1080 или 720×576) и разумного числа пикселей; большие области отбрасывать.
      Критерий: поток с `w=h=4096` не даёт 16–64 МБ на область и не останавливает ретранслятор.
- [ ] **2.4. OOM в текстовых субтитрах.** `src/core/webvtt.c:594`, `src/core/util.c:276, 287`:
      проверять `strdup`/`sl_insert`; при `NULL` не добавлять реплику/строку.
      Критерий: при нехватке памяти нет `strcmp(NULL, …)`.
- [ ] **2.5. Время WebVTT/TTML.** `src/core/webvtt.c:149`, `src/ui/subs.c:268`: решить, что делать
      без `X-TIMESTAMP-MAP`/при «голом» TTML (0 или базовая метка потока). Сначала проверить на
      реальном HLS; если нужно — передавать `relay_base_pts()` в загрузчик.
      Критерий: субтитры с `MPEGTS:0` и ненулевой первой меткой не исчезают молча.

Коммиты:

```text
Субтитры fMP4: смещение и размер образца проверяются без переполнения; пустой trun не крутит цикл
CEA-708: SPL и BS не выводят колонку за ширину окна 42
DVB-субтитры: область ограничена экраном и числом пикселей — нет OOM и длинной копии под замком
Субтитры: strdup реплик и строк проверяется — OOM не даёт NULL в strcmp
```

## 3. Каналы, плейлисты, программа (критично/важно)

- [ ] **3.1. UAF при смене плейлиста.** `src/ui/guide.c:193-199`, `src/ui/menu.c:141-151`:

## Риски

- Ретранслятор — общий для всех каналов; после правок 1.1–1.5 обязательны тесты RTSP/UDP/HLS и
  прогон с реальным провайдером на ТВ.
- Динамические заголовки HTTP увеличивают память на соединение; ограничить разумным максимумом
  (например, 64 КБ) и освобождать в `hs_close`.
- `tv_playlist_changed` в ветке «файла нет» может изменить порядок открытия гида; проверить
  сценарий «гид → плейлист → каналы».
- Ограничение области DVB 1920×1080 может отбросить нестандартный поток; проверить на записях BBC
  и французского ТВ из `tests/data`.
- AppId `99010100` считается настоящим; если это не так — до публикации откатить `app.json` и
  README.
