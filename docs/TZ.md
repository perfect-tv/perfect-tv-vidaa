# ТЗ: Perfect TV для VIDAA (нативное приложение)

Полноэкранный IPTV-плеер для пульта на телевизорах VIDAA OS (Hisense, Toshiba): эфир, архив, программа, ТВ-гид,
напоминания, избранное, блокировка. Эталон поведения — Android-версия Perfect TV (её ТЗ, раскладка и оформление);
здесь — то же, переложенное на нативное приложение VIDAA, и всё, чем VIDAA отличается. Раскладка — `docs/controls.md`,
оформление — `docs/design.md`, что сделано и проверено — `docs/PLAN.md`.

## 1. Платформа

| | |
|---|---|
| ОС | VIDAA OS (MTK9655 / MTK9618, проекторы MStar), ARM32 hard-float, glibc 2.25–2.28 |
| Язык | C11, `zig cc -target arm-linux-gnueabihf.2.28`, свои файлы — `-Wall -Wextra -Werror` |
| Каркас | SDK нативных приложений VIDAA: `fw/` (холст, FreeType, JSON, HTTPS на OpenSSL, пул потоков, стек экранов, настройки), `fw/tv_shell.c` (жизненный цикл APM, окно DirectFB 1.4, пульт evdev, журнал, обработчик падений) |
| Графика | DirectFB 1.4 через оболочку: окно ARGB во весь экран, программный холст 1920×1080; пиксели с alpha 0 — «дыра» к видеоплоскости |
| Видео | `vendor/player-hmc.c`: FFmpeg разбирает поток, кадры (H.264/HEVC; AAC/AC-3/E-AC-3) — в системный плеер ТВ (HMC, режим ES); отказ по кодекам — `vendor/sw_player.c` (FFmpeg + ALSA, MPEG-2, MP2) |
| Сеть | свой потоковый HTTP(S) на OpenSSL (`core/http.c`) для плейлиста и программы; логотипы — `http_do` каркаса; корневые сертификаты вшиты в бинарник |
| Хранение | каталог данных (`PTV_DATA_DIR` из стартового скрипта): JSON-настройки каркаса, файлы плейлистов, каналов, программы, напоминаний |
| Пакет | `.ipk` для магазина VIDAA (`tools/pack.py`), подпись — набором автора SDK |

Нет SQLite и Android-сервисов, поэтому хранение своё (§3). Нет системной клавиатуры — своя экранная (§9). Нет
системных уведомлений — напоминания только пока приложение открыто.

## 2. Процесс и жизненный цикл

Один процесс: стартовый скрипт пакета → `perfecttv-app --ui` → `tv_shell_run` (SDK): регистрация в APM, DirectFB,
окно, узлы пульта, главный цикл (`poll` 16 мс). Приложение — один экран каркаса (`root` в `main.c`), внутри — свой стек
слоёв. Выход: «Назад» ×2, Home, таймер сна → `app_quit()`; оболочка закрывает плеер (`on_shutdown`: `pl_shutdown`),
сохраняет настройки, сообщает APM и завершает процесс `_exit` (glibc `exit()` с SDK APM даёт `abort`).

## 3. Данные

Время — unix-секунды (UTC).

| Файл | Содержимое |
|---|---|
| `settings.json` | настройки (`core/prefs.c`), «где остановились», пользовательские данные плейлистов: `fav.<id>`, `hist.<id>`, `hidc.<id>`, `hidg.<id>`, `lockc.<id>`, `lockg.<id>`, `score.<id>` (ключи каналов через `\n`), `hname.<ключ>` — название скрытого канала |
| `playlists.json` | плейлисты: id, имя, адрес, режим программы, свои источники, источники из заголовка, время загрузки, число каналов, ошибка, ETag / Last-Modified |
| `channels_<id>.tsv` | каналы плейлиста (строка — канал, поля через TAB, `\t \n \\` экранированы): номер, имя, адрес, категория, логотип, tvg-id, tvg-name, tvg-shift, архив (тип, источник, глубина), User-Agent, Referer, `#EXTHTTP` |
| `epg/<хэш адреса>/meta.json` | источник программы: текущая выгрузка `gen`, время загрузки, ETag / Last-Modified, ошибка, хэш нужных каналов `want_hash`, подпись плейлистов `users_sig`, число передач |
| `epg/<хэш>/c<gen>.tsv` | каналы XMLTV (все): id, иконка, display-name — через TAB, строка — канал |
| `epg/<хэш>/d<gen>.bin` | куски «канал + сутки (UTC по началу передачи)», каждый сжат zlib: передачи по 28 байт (начало, конец, смещения пяти строк), затем строки куска |
| `epg/<хэш>/i<gen>.bin` | оглавление: заголовок, каталог корзин (1–256, по хэшу id канала, ~32 канала в корзине), в корзине — каналы (id, число передач) и их куски (начало первой, конец последней, передач, длины, смещение) |
| `reminders.json` | напоминания: ключ и имя канала, плейлист, начало и конец, название, «отложено до», «показано» |

- **Ключ канала** — `names_key(имя)`: нижний регистр без пробелов и знаков ASCII. Избранное, история, скрытое,
  блокировки и напоминания держатся на нём и переживают перезагрузку плейлиста.
- Перезагрузка плейлиста пишет каналы во временный файл и заменяет старый только после успешного разбора: пока идёт
  загрузка, интерфейс показывает старый список; ошибка — старый список остаётся.
- **Программа не отображается в память и целиком не читается**: распакованный XMLTV бывает 1–3 ГБ, а у процесса
  ARM32 около 3 ГБ адресов на всё. Хранятся передачи только сопоставленных каналов **всех плейлистов с этим
  адресом** (источник общий) в окне `[начало сегодняшнего дня − (глубина архива канала + 1 сутки); сейчас + 8 суток]`.
- **Чтение** (`data/epg.c`): корзина оглавления разбирается при первом обращении к её каналу, кусок — `pread` и
  распаковка в общий кэш (~100 кусков, 1–5 МБ). Кусок, нужный в этом или прошлом кадре (`epg_frame`), не вытесняется:
  строки передачи живут минимум до следующего кадра; дольше — копировать. В памяти постоянно — только слоты
  (сопоставленные с текущим плейлистом каналы XMLTV: id и иконка). Сопоставление (`repo_map_epg`) читает `c<gen>.tsv`
  построчно.
- **Сборка** (рабочий поток): каналы XMLTV пишутся в `c<gen>.new` сразу; передачи канала копятся до смены канала
  (XMLTV идёт по каналам подряд; встретился снова — его куски читаются обратно), затем прошлое прежней выгрузки
  (передачи до первой новой, не старше окна; канал пропал из XMLTV — всё его прошедшее), порядок, повторы (остаётся
  новая), перекрытия (обрезка по следующей), нарезка по суткам, zlib уровня 1 → `d<gen>.new`. Память — один канал и
  оглавление: 10 000 каналов × 17 суток (2 ГБ XML, 3,6 млн передач) — +6 МБ на пике, 300 МБ на диске
  (`PTV_BENCH=1 build/host/perfecttv-tests`). В конце — оглавление, переименование (оглавление последним), `meta.json`
  с новым `gen`; файлы прежней выгрузки удаляет `epg_prune` (кэш держит свои копии кусков).
- **Когда загружать заново**: срок «Обновлять программу каждые», нет выгрузки, или сменилась подпись плейлистов
  источника (новый плейлист с этим адресом, перезагружен плейлист). Сборка считает хэш нужных каналов: тот же —
  условный запрос (304 — только время), другой — полная загрузка без ETag (304 оставил бы новые каналы без программы).
- **Уборка** (`repo_gc_epg`, при запуске, удалении плейлиста, смене его источников; не во время загрузки): папки
  источников, на которые не ссылается ни один плейлист, файлы чужих выгрузок, файлы прежнего формата `epg_*`.

## 4. Потоковый разбор плейлиста

Как в Android-версии (§4 её ТЗ): HTTP-тело → распаковка по первым байтам (`1F 8B` gzip, в том числе склеенный; `PK`
zip — первый файл; `FD 37 7A 58 5A` xz — ошибка «формат») → построчный разбор: BOM, CRLF, `#EXTM3U` с `url-tvg` /
`x-tvg-url` / `tvg-url` (несколько через запятую или пробел, `http`, `https`, `file`), `catchup*`, `tvg-rec`,
`timeshift`, `tvg-shift`; `#EXTINF` — название после первой запятой вне кавычек, атрибуты `key="v"`, `key='v'`,
`key=v`; `#EXTGRP`, `#EXTVLCOPT` (user-agent, referrer), `#EXTHTTP`; строка адреса (http, https, rtmp, rtsp, udp, rtp,
mms) завершает канал; YouTube пропускается; без `#EXTINF` — «Ch N»; значки `ⓢⓖⓥⓞ` убираются. Первая непустая строка
не `#EXTM3U` — ошибка «формат». Ошибки: `no_url | <сеть> | http_<код> | format | empty | xz` — на экране ошибки
(«OK — повторить, Меню — настройки») и в настройках плейлиста. Условный запрос `If-None-Match` / `If-Modified-Since`,
304 — без разбора. Адрес может быть путём к файлу на ТВ (`/…` или `file://…`, например USB).

## 5. Потоковый разбор программы (XMLTV)

Свой разборщик на уровне байтов (`data/xmltv.c`, порт веб- и Android-версии): у `<programme>` читается открывающий
тег, канал сравнивается побайтно с каналом предыдущей передачи, ненужная передача пропускается поиском `</programme>`
без разбора; фильтр по времени — до разбора содержимого. Кодировка — из пролога: UTF-8, windows-1251, koi8-r,
iso-8859-1. Языки: язык интерфейса, затем `ru`, затем первый. Время `yyyyMMddHHmmss ±hhmm` (`±hh:mm`; без смещения —
UTC; без секунд/минут). Нет `stop` — до начала следующей передачи канала, последняя — час. Перекрытия обрезаются по
следующей; одинаковое начало — остаётся новая. Каналы плейлиста сопоставляются с `<channel>` перед первой передачей
(§6); `<channel>` после передач — пересчёт. Загрузка — в рабочем потоке, по одному источнику; прогресс («Программа
загружается… 45 %») — в гиде и настройках. Обновление — при запуске, если данным больше «Обновлять программу каждые»
(6 / 12 / 24 ч), и каждую минуту проверяется срок.

## 6. Сопоставление каналов с программой

По источникам плейлиста по приоритету (режим «Из плейлиста» / «Плейлист + свои» / «Только свои», не больше восьми):
`tvg-id` == id канала XMLTV; иначе ключ сопоставления `tvg-name`, затем имени канала == ключ одного из `display-name`.
Ключ сопоставления — короткое имя (без «(архив)», «телеканал», «канал»/«тв» в конце, «orig»/«50»; «(+2)» → «+2»; знаки →
пробел; «канал 5» → «канал5») с транслитом похожих букв (`н→h`, `в→b`, `з→3`…). Сопоставление пересчитывается при
открытии плейлиста и после загрузки программы. `tvg-shift` (часы) сдвигает программу канала при показе. Логотип:
`tvg-logo`, иначе иконка канала XMLTV (настройка «Приоритет логотипов» меняет порядок).

## 7. Время

`clock_now()` — время ТВ с поправкой по заголовку `Date` ответов сервера, если расхождение больше 30 с. Часовой
пояс — системный (`localtime`), если на ТВ он не задан или неверен — настройка «Часовой пояс» (UTC−12 … UTC+14 по
получасу). Форматы: «Сегодня» / «Вчера» / «Завтра» / «Пн, 02.11»; вкладка даты — «пн» / «2 нояб.».

## 8. Воспроизведение

- **Эфир**: адрес канала с заголовками User-Agent, Referer, `#EXTHTTP` (системному плееру — через опцию FFmpeg
  `headers`; программный плеер заголовков не умеет). Открытие и закрытие — в рабочем потоке, переключения сливаются
  (последнее побеждает); ←/→ — 0,7 с задержки, инфопанель и карусель сразу.
- **Ошибки**: поток упал или кончился — повтор через 2, 5, 10 с, затем экран «Канал недоступен» с причиной и кодом
  (OK — повторить). Отказ системного плеера по кодекам или «нет плеера» — программный плеер (MPEG-2, MP2).
- **Архив** — шаблоны как в Android-версии (`data/catchup.c`, тесты `test_catchup`): shift/timeshift, append, default,
  flussonic*/fs, xc и подстановки `${…}`. Шаблон с длительностью (`${duration}`, `${end}`, `${(d)…}`, `${(e)…}`) — окно
  передачи: ссылка с её начала, длительность — до конца передачи или до «сейчас», позиция внутри ссылки — перемоткой
  плеера; перемотка внутри окна — `PL_SEEK_ABS`, за его пределами — новая ссылка. Шаблон без длительности (shift) —
  ссылка с нужного момента. Конец окна — следующая передача; догнали эфир (30 с) — эфир. **Flussonic** — всегда
  `archive-START-DURATION`, EVENT-ссылка `-now` не используется (FFmpeg начинает её у края эфира, §AGENTS.md).
- **Перемотка**: нажатие — 30 с, удержание — от 30 с до 10 мин эфира в секунду, применяется через 0,9 с после
  последнего нажатия (или OK); границы — глубина архива канала и «сейчас».
- **Пауза эфира**: плеер на паузе, время паузы запоминается; продолжение позже 3 с — архив с момента паузы (у канала
  с архивом), иначе снова эфир.
- **Формат кадра** (вписать / растянуть / 16:9 / 4:3) — `PL_ASPECT` системного плеера, запоминается.
- **Звук**: дорожки системного плеера; другая дорожка того же формата — на месте, другого — отказ (ограничение режима ES).
- **Качество** (SD/HD/FHD/4K) — по высоте видео; бейдж «SW» — программный плеер.
- **Таймер сна**: 15–120 мин, за минуту — тост, по сроку — выход.
- **Адаптивная сортировка**: канал, который смотрели больше 5 минут подряд, получает очко.

## 9. Интерфейс

Один экран ТВ (`ui/tv.c`) с видео, инфопанелью, каруселью, набором номера и тостами, поверх — стек слоёв
(`ui/layer.c`): верхний слой получает клавиши, без слоёв — плеер. Слои: ТВ-гид, «Программа и архив», карточка
передачи, меню канала, недавние каналы, напоминание, «Управление», скрытое, PIN, настройки, формы, выбор из списка,
подтверждение, мастер. Состав и клавиши — `docs/controls.md`.

- **Стартовый экран.** Нет плейлистов — мастер «Добавить плейлист» / «С телефона (QR)» / «Выход». Плейлист без каналов — загрузка
  («Загружаем плейлист… N каналов») или экран ошибки. Иначе — последний канал (настройка «Запускать последний канал»)
  или гид.
- **Телетекст и субтитры телетекста** (`core/ttx.c` — перенос `Ttx.kt` Android-версии без X/26; `core/relay.c`;
  окно `ui/teletext.c`). Системный плеер дорожки телетекста не отдаёт, `vendor/` не правится, второе подключение к
  провайдеру недопустимо (у многих — одно на аккаунт). Поэтому, когда пользователь открыл телетекст (меню канала →
  «Телетекст», кнопка TEXT) или включил субтитры (меню → «Субтитры (телетекст)», кнопка SUBTITLE; запоминается за
  каналом — `subs.<ключ>` в хранилище), поток идёт через ретранслятор на 127.0.0.1:47390 (занят — до 47399):
  `/s?u=<адрес>&h=<заголовки канала>`. По настройке «Сеть → Поток через приложение» (по умолчанию вкл.) так идут
  все HTTP/HLS-каналы — дорожки известны сразу, телетекст открывается без переоткрытия; канал, который через
  ретранслятор не открылся (ошибка до первого кадра), сразу открывается напрямую (попыткой не считается) и попадает
  в список `relay.direct` (хранилище; «Каналы с прямым подключением» — сколько, OK — сброс); при явно включённом
  телетексте — тост «Канал не открывается через приложение…». Ретранслятор прозрачен: Range, Cookie, повторы — дело
  плеера; заголовки запроса плеера уходят провайдеру (кроме Host, Connection, Accept-Encoding и т. п.; заголовки
  канала важнее), ответ — тот же статус (206, 304, 4xx) и заголовки (кроме длины и заголовков соединения), в
  Set-Cookie убираются Domain, Secure и SameSite (плеер ходит на 127.0.0.1). Провайдеру — `Accept-Encoding: identity`
  (плейлист переписывается, байты — как есть). Редиректы ретранслятор проходит сам. Устройство — **один поток с циклом событий
  epoll** («ptv-relay»): неблокирующие сокеты и TLS (OpenSSL, `SSL_ERROR_WANT_READ/WRITE`), на соединение плеера —
  состояние, к нему — соединение с провайдером (адрес → connect → TLS → запрос → заголовки → тело). До 64 плееров
  (сверх — 503). DNS (`getaddrinfo` блокирующий) — короткий поток на запрос («ptv-dns»), итог — через трубу в цикл,
  адреса кэшируются на минуту. **Обратное давление**: в очереди к плееру больше 256 КБ — провайдер не читается, пока
  плеер не разберёт половину (память постоянна, у провайдера не выкачивается лишнее). Расшифрованное TLS, о чём epoll
  не знает (`SSL_pending`), дочитывается следующим проходом. Таймауты: адрес, соединение, TLS, заголовки — 20 с;
  тело стоит — 20 с; плеер молчит между запросами — 15 с. **Keep-alive**: к провайдеру — пул в цикле (до 8, простой
  20 с; в пуле сокет слушается — закрытие сервером видно сразу; если соединение из пула умерло до первого байта
  ответа — запрос повторяется на новом); к плееру — запросы подряд в одном соединении (ответ с длиной —
  Content-Length, без длины — кусками; эфир TS — один длинный ответ). Редиректы — новым запросом того же плеера
  (до 8). Объекты, закрытые при обработке пачки событий, освобождаются после неё. Поток разбирается — MPEG-TS: PAT → PMT → дескриптор
  0x56/0x46 (язык, страницы субтитров типов 2 и 5) → PES → `ttx_feed`; дескриптор 0x59 (DVB-субтитры картинками)
  только отмечается — «пока не показываем». Ответ `#EXTM3U` — плейлист HLS: строки-адреса и `URI="…"` в тегах
  переписываются на ретранслятор с абсолютным адресом (от адреса после редиректов, `hs_url`) и теми же заголовками.
  Новая ссылка — `relay_reset` (страницы, метка времени); соединения прежней ссылки разбор не трогают (поколение).
  UDP/RTSP — нельзя («только для потоков HTTP и HLS»). Страницы — до 3000 (код подстраницы «бежит» — сброс),
  субтитры — история 200 с метками PTS; на экране — последняя не позже кадра `relay_base_pts() + pl_position()·90000`,
  страница субтитров — первая, помеченная C6, объявленная в дескрипторе или 888. Кириллица — по коду набора (X/28,
  M/29) или по языку дорожки (rus/ukr/bul/bel/srp/mkd/kaz). Окно: сетка 40 × 25 (ячейка 4:5), цвета уровня 1,
  мозаика (сплошная и раздельная), двойная высота, скрытое (OK), строка 0 — «P100» и заголовок потока (набор номера —
  «P12-»). Субтитры — строки «окон» (или всей страницы) на тёмных плашках над инфопанелью. Окно телетекста — как у
  Android-версии (`docs/controls.md`): поверх видео по умолчанию (слой не «закрывает» экран, клетки — с
  прозрачностью: чёрное 40 %, цвета 88 %, знаки с тенью), ←/→ — принятые страницы, ↑/↓ — подстраницы, клавиатура
  6 × 3 с кругом d-pad и диапазонами страниц, меню (клавиатура и фон — `ttx_keypad`, `ttx_mix` в настройках),
  автолистание подстраниц, мигание, двойная ширина и высота. Значки «SUB» / «TTX» в инфопанели.
- **Субтитры: DVB и WebVTT** (`core/dvbsub.c`, `core/webvtt.c`, выбор и показ — `ui/subs.c`). Дорожки знает
  системный плеер (`pl_sub_*`: подпись — язык, кодек FFmpeg), но не показывает; показываем сами из потока через
  ретранслятор. **DVB** (EN 300 743): дескриптор 0x59 в PMT — по записи на дорожку (у одного PID бывают обычные и
  для слабослышащих на разных страницах композиции); PES выбранной — в свой декодер: страница, области, палитры
  (по умолчанию — таблицы стандарта; YCrCb BT.601 «студийный»), объекты (коды длин серий 2/4/8 бит, таблицы
  перекодировки, поля верхнее и нижнее), размер экрана; «конец набора» — показ (области ARGB, PTS, page_time_out).
  Сверено на записях BBC и французского ТВ (samples.ffmpeg.org). PES готов по `PES_packet_length`, не дожидаясь
  следующего. **WebVTT**: ретранслятор при переписывании главного плейлиста запоминает `#EXT-X-MEDIA:TYPE=SUBTITLES`
  (имя, язык, адрес провайдера, заголовки канала); выбранную читает свой поток («ptv-vtt», блокирующий клиент,
  keep-alive): эфир — плейлист раз в полдлительности сегмента, новые сегменты (сначала последние 4); запись — сегменты
  около позиции плеера; реплики — через `X-TIMESTAMP-MAP` (нет — MPEGTS 0), теги и сущности убираются, до 3000
  реплик. Остановка не ждёт поток: флаг отмены (HTTP-клиент прерывается), задачу освобождает сам поток.
  **Выбор** — ключ «ttx» / «dvb:<язык>:<слабослышащие>» / «vtt:<язык>», хранится за каналом (`subs.<ключ>`),
  каждый кадр сопоставляется с дорожкой ретранслятора (тот же язык, иначе первая того же вида). Выбраны субтитры, а
  поток напрямую — переоткрыть через ретранслятор. Канал, не открывшийся через ретранслятор, попадает в список прямых,
  только если напрямую заиграл.
- **Описания TMDB** (`data/tmdb.c`; «Настройки → Описания (TMDB)»): ключ v3 (`api_key` в запросе) или токен v4
  (длиннее 40 знаков — заголовок `Authorization: Bearer`), ввод с клавиатуры или с телефона (та же страница QR, вид
  `PHONE_TMDB`: ключ, адреса API и картинок), адреса API и картинок (стандартные или прокси), «Проверить» (поиск
  «Ирония судьбы», 1975: 401 — «Неверный ключ»), «Удалить ключ». В раскрытой инфопанели (↓↓): картинка — EPG →
  backdrop TMDB (w780) → постер → логотип; в строке тегов — год и «TMDB 7.8»; описание — EPG, нет — TMDB. Подбор —
  как у Android-версии: `tmdb_query` (нижний регистр, без возраста, года, сезонов и серий, «Дайджест», «Сборник N»,
  «Часть N»; кавычки «…» в начале — только их содержимое; POSIX-регулярки по байтам с кириллицей буквально — на ТВ
  локаль «C»), год — «(2010)» в названии или «1997 г.» в начале описания, сходство — Левенштейн по кодовым точкам
  после `search_fold`, порог 0,72 (0,6 при совпадении года), бонус за год и картинку; без года — только единственный
  результат со сходством ≥ 0,9. `/search/multi`, язык интерфейса, без person. Один запрос за раз (следующий — после),
  кэш 48 ответов в памяти; ошибки сети не кэшируются. Ключ в журнал не пишется (`tmdb_error=network|http_N`).
  Атрибуция TMDB — в «О программе → Лицензия», `NOTICE`, `credits`.
- **Резервная копия** (`data/backup.c`; «Настройки → Данные»). Один JSON `backup-ГГГГММДДЧЧММСС.perfecttv`:
  `app`, `format` (1), `platform` (`vidaa`), `created`, `settings` — всё хранилище `settings.json` (настройки,
  избранное, недавние, скрытое, блокировки, очки, PIN, недавние запросы), `playlists` (без каналов), `reminders`.
  «Сохранить» — в `PerfectTV/` на первом накопителе (переживёт удаление приложения, переносится на другой ТВ) и в
  `backups/` каталога данных (последние 5); путь — в тосте. «Восстановить» — список копий с флешек (`PerfectTV/` и
  корень) и из памяти ТВ, новые сверху («17.11.2026 03:31 · флешка»), подтверждение, при заданном PIN — PIN (копия
  заменит и его). Восстановление: ключи хранилища — заменить целиком (сначала удалить все, перечень — из файла),
  `playlists.json` без времени загрузки и ETag, `reminders.json`, файлы каналов удалить; затем `tv_restart`
  (настройки, язык, `repo_reload`, как при запуске) — плейлист скачивается заново. Программа (по адресу) остаётся.
  Не копия Perfect TV — «Это не резервная копия Perfect TV». Копии Android-версии — другой формат, не читаются.
- **Файл с флешки** (`core/usb.c`, окно `ui/files.c`). Точки монтирования VIDAA неизвестны: корни — из
  `/proc/mounts`: файловые системы флешек (vfat, exfat, ntfs, ntfs3, fuseblk, tntfs, ufsd, hfsplus…) или точки под
  `/mnt`, `/media`, `/run/media`, `/storage` со «usb» / «sd» / «disk» в пути (кроме squashfs, ubifs, tmpfs, overlay
  и `/mnt/tvroot`). В журнал — `usb_roots=N пути`, а если ничего не нашлось — `candidates=` (точки и типы), чтобы
  по журналу с ТВ уточнить правила. `PTV_USB_ROOT` — свой корень (ПК). Плейлист с флешки грузится как файл (путь).
- **Поиск** (`data/search.c`, окно `ui/search.c`, клавиатура — общая с формами `ui/kbd.c`). Каналы — сразу в
  главном потоке. Передачи — задача `pool_submit` через 0,3 с после набора: для каждого источника с выгрузкой —
  снимок (хэш, `gen`, id канала XMLTV и окно каждого канала плейлиста: от «сейчас − архив» или «сейчас» до «+7 суток»,
  со сдвигом `tvg-shift`), `epg_search` открывает выгрузку сам (кэш главного потока не трогается), читает только куски,
  пересекающие окно, сравнивает названия после `search_fold` (нижний регистр, ё → е, знаки → пробел). До 2000 находок,
  в разделе — 30. Новый запрос отменяет идущий (флаг `cancel`); сменился список каналов (`R.rev`) — результат
  отбрасывается и поиск повторяется. Недавние запросы — `search.recent` в `settings.json`.
- **Ввод с телефона** (`core/phone.c`, `core/qr.c`, окно `ui/phone.c`; кнопка «С телефона (QR)» в форме плейлиста
  и в мастере). Приложение слушает TCP 47381 (занят — до 47390) на всех адресах, QR-код (версия 5-L, свой
  кодировщик, сверен с эталонной библиотекой) — `http://<адрес ТВ в сети>:<порт>/<ключ>`, ключ — 16 знаков из
  `/dev/urandom`. Страница (язык интерфейса, CSP без скриптов) — поля «Адрес плейлиста», «Название», «Адрес
  программы XMLTV»; адреса — только `http(s)://`. Ответ заполняет форму (адрес программы — в свои источники, режим
  «из плейлиста» → «плейлист + свои»), фокус — на «Сохранить». Страница одноразовая: после приёма или через 10 минут
  сервер закрывается (OK — новый код), закрыли окно — тоже. Сервер неблокирующий и опрашивается из `tick` окна в
  главном потоке. Ключ и адрес в журнал не пишутся. Адрес ТВ — первый IPv4 не петля (eth/wlan важнее мостов).
- **Ввод текста** — своя экранная клавиатура (`ui/form.c`): 11 × 5, ЙЦУКЕН / QWERTY / символы с кусками адресов
  (`http://`, `https://`, `.m3u8`, `.xml`, `.gz`…), ряд цифр, служебный ряд (⇧, язык, символы, пробел, ⌫ — удержание OK
  очищает, «Готово»). Цифры пульта вводятся сразу, CH+ — стереть.
- **Форма плейлиста**: название, адрес, режим программы, свои источники (каждый — строкой; пустой — удалить),
  адреса из плейлиста — только чтение; «Сохранить» / «Удалить» (с подтверждением) / «Отмена». Сохранили с новым
  адресом — плейлист перекачивается; новый плейлист становится текущим, если текущего нет.
- **Язык** — русский и английский (`core/strings.def`), по умолчанию русский, если переменных окружения нет
  (на ТВ их обычно нет); меняется на ходу.

## 10. Настройки

Два столбца: разделы и пункты (`ui/settings.c`), клавиши — `docs/controls.md`.

- **Плейлисты**: плейлисты (имя, «N каналов · когда загружен» или ошибка; OK — форма), «Добавить плейлист»,
  источники программы текущего плейлиста со статусом, «Обновить программу».
- **Просмотр**: глубина архива по умолчанию (1–14 дн.), скрывать инфопанель через (3/5/7/10 с), клавиша ↑ в плеере
  (программа / недавние), запускать последний канал, напоминать о передаче (когда начнётся, за 1–10 мин),
  принимать любые сертификаты (по умолчанию да), формат кадра, обновлять программу каждые, обновлять плейлист каждые.
- **Внешний вид**: язык, часовой пояс, размер интерфейса (меньше / нормальный / больше: высота экрана 54 / 48 / 43,2 em),
  номер канала (не показывать / рядом с названием / бейдж на логотипе), вид гида, шапка гида, подсказки клавиш,
  приоритет логотипов.
- **Список каналов**: адаптивная сортировка, сброс очков, скрытые категории и каналы.
- **Блокировка**: задать / сменить PIN (сначала старый), убрать PIN, спрашивать PIN (каждый раз / один раз до выхода),
  ввод PIN (кольцо / ряды / клавиатура).
- **Данные**: очистить кэш логотипов, удалить сохранённую программу (с подтверждением), папка данных.
- **О программе**: версия, исходный код, лицензия.

## 11. Нефункциональные требования

- Плейлист на 10 000 каналов и программа на сотни мегабайт XML — без чтения в память целиком; передачи фильтруются
  до записи, в куче — только записи текущей загрузки (28–32 байта на передачу) до записи файла.
- Интерфейс не блокируется загрузками и открытием потока (рабочие потоки).
- Кадр рисуется только при изменениях (клавиша, событие, раз в секунду для часов), без выделений памяти на кадр в гиде.
- Журнал: события запуска, загрузок, плеера и падений — без адресов потоков и ключей.
