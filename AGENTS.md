# AGENTS.md — Perfect TV для VIDAA (нативное приложение)

Документация и комментарии — на русском. Поведение и вид описаны здесь и в `docs/`: ТЗ (`docs/TZ.md`), управление
(`docs/controls.md`), оформление (`docs/design.md`), план и что проверено (`docs/PLAN.md`). Эталон поведения —
Android-версия Perfect TV; чем VIDAA отличается — записано в `docs/TZ.md`. Чего нет в документах — решить и дописать туда же.

## Команды

- `python3 tools/build.py --tests` — юнит-тесты на ПК (M3U, XMLTV, распаковка, шаблоны архива, имена, хранилище программы, время, строки).
- `python3 tools/build.py --host` — интерфейс на ПК с заглушкой плеера; сценарий клавиш и снимки — README, «Проверка на ПК».
- `python3 tools/build.py` — ELF ARM32 для ТВ (zig 0.13, `-Werror`); `python3 tools/pack.py` — `.ipk`.
- SDK — `../native_app` или `VIDAA_SDK`; zig — `native_app/toolchain/zig-linux-x86_64-0.13.0` или `ZIG`.

## Правила

1. **Каркас SDK (`fw/`) и `vendor/` не править** — они в SDK, общие для приложений; `vendor/` проверен на ТВ. Не хватает — свой модуль в `src/`.
2. **Плейлист и программа — только потоком** (`core/http.c` → `core/unpack.c` → `data/m3u.c` / `data/xmltv.c`): файл целиком в память не читать. Программа — куски «канал + сутки» (`data/epg.c`): ни сборка, ни чтение не держат её целиком и не отображают файлы в память (2 ГБ XMLTV, ARM32).
3. **Время** логики — `clock_now()` (unix-секунды с поправкой по `Date` сервера), часовой пояс — `clock_tz()`; `app_now()` — только для таймеров интерфейса.
4. **Потоки.** Рисует и трогает `R`, `T`, слои только главный поток. Сеть и разбор — `pool_submit` (work в рабочем потоке, done — в главном). В рабочем потоке не читать `R`: снимок нужных полей делается до запуска (см. `epg_start`). Исключение — ретранслятор `core/relay.c`: свои потоки на время просмотра (соединение плеера живёт, пока идёт видео; пул бы встал), общее с главным — только `ttx` и счётчики под замком.
5. **Указатели на каналы** (`channel *`) живут до `repo_select()`: после перезагрузки плейлиста `tv_playlist_changed()` закрывает слои, которые их держат. Строки программы (`prog.title` и т. п.) — из кэша кусков `epg.c`, живут до следующего кадра (`epg_frame` в `root_draw`); окно, которое держит их дольше, копирует (`card_open`).
6. **Освобождение при передаче владения** — обнулять и указатель, и счётчик; `free`-функции терпят `NULL` (урок VidaaTV, BUILD-GUIDE, грабли № 15).
7. **Рисование.** Холст 1920×1080 ARGB, alpha 0 — «дыра» к видео. Полупрозрачное поверх видео — только `d_*` из `ui/u.c` (честная прозрачность); `gfx_*` каркаса делают пиксель непрозрачным. Размеры — в em (`E()`, 1 em = высота / 48 при нормальном размере), цвета — `C_*` из `ui/u.h`. Стрелок ←↑→↓ в шрифтах нет: `d_text`/`d_lines` рисуют их значками; другие знаки вне кириллицы и латиницы — проверять снимком.
8. **Клавиши** — только через `ui/keys.c` (сырые события evdev из `raw_key` оболочки) и слои `ui/layer.c`: долгие нажатия, удержание ↑/↓ своим таймером. Раскладку менять вместе с `docs/controls.md` и окном «Управление» (`popups.c`, строки `S_HELP_*`).
9. **Строки интерфейса — только `src/core/strings.def`** (английский и русский рядом, счётные — формы через «|»). Не кэшировать в статических полях — язык меняется на ходу. `test_lang` проверяет, что подстановки в обоих языках совпадают.
10. Пользовательские данные привязаны к ключу канала `names_key(name)`, а не к номеру.
11. **Журнал без адресов потоков и ключей** (журнал может уйти на сервер). FFmpeg — через фильтр `ff_log` в `player.c`.
12. Новый `.c` — добавить в `sources` в `app.json`.

## Тонкости (не очевидно из кода)

- **Телетекст и субтитры — через ретранслятор.** `vendor/player-hmc.c` отбрасывает всё, кроме видео и звука, а `vendor/` не правится: включили телетекст или субтитры — плееру уходит `http://127.0.0.1:47390/s?u=…&h=…` (`open_url` в `tv.c`), байты идут как есть, HLS-плейлисты переписываются, TS разбирается по пути (`relay_tap`). Только HTTP/HTTPS; по умолчанию поток идёт напрямую. Время субтитра — `relay_base_pts()` (первая метка видео/звука, что прошла через ретранслятор) + `pl_position()`; проверить на ТВ, что позиция системного плеера считается от той же метки.

- **Архив Flussonic.** Всегда окно `archive-START-DURATION.m3u8` (для идущей передачи — до «сейчас»); EVENT-ссылку `-now` не используем: FFmpeg-демуксер HLS без `#EXT-X-ENDLIST` начинает у края (live_start_index −3), а параметров ему через `vendor/player-hmc.c` не передать. Дошли до конца окна — следующая ссылка (`tv_tick`, `PL_ENDED`), догнали эфир — эфир.
- **Позиция архива** = `arc_url_start` + позиция плеера в ссылке (`pl_position`). Для шаблонов без длительности (shift) ссылка начинается с нужного момента, для шаблонов с `${duration}`/`${end}` — с начала передачи, и плеер перематывается внутри ссылки (`start` в `hmc_player_open`).
- **Пауза эфира**: системный плеер ставится на паузу; продолжение позже 3 с у канала с архивом — архив с момента паузы, без архива — снова эфир.
- **Клавиши.** Оболочка отдаёт каждое событие в `raw_key`; приложение забирает все (`return 1`), Home — `app_quit()`. Повтор `value 2` пульта используется только для ←/→ и CH±; ↑/↓ повторяются своим таймером.
- **Программа — общая для плейлистов с одним адресом**: сборка берёт каналы всех таких плейлистов из их `channels_<id>.tsv` (`repo_read_wants`, в рабочем потоке). Сменились плейлисты источника — `users_sig` в `meta.json` не совпал, и источник проверяется заново; сменились нужные каналы — `want_hash`, и условный запрос не делается. Выгрузки нумеруются (`gen`): новая пишется рядом, прежняя удаляется после переоткрытия (`epg_prune`).
- **Логотипы** — `img_get` каркаса (кэш в памяти, только http/https); пока картинки нет — монограмма. Неудачный адрес каркас больше не запрашивает до очистки кэша.
- **Каталог данных** может быть только для чтения (uid 301): стартовый скрипт выбирает `/APPS/perfecttv-native-data` или `/tmp/…` и экспортирует `PTV_DATA_DIR`.
- **Ключ «Все каналы» и «Избранное»** — `"\x01all"` / `"\x01fav"` (`repo.h`): не совпадут с категорией плейлиста.

## Перед завершением

`python3 tools/build.py --tests && python3 tools/build.py --host && python3 tools/build.py`. Изменения интерфейса —
снимок экрана на ПК (`build/host/perfecttv-host … shot:имя`). Запуск на ТВ — отдельный пункт `docs/PLAN.md`: «собирается» не значит «работает».
